# RJ NETWORK V2.4 — Customer Portal

## Added
- Customer ID + password login.
- PBKDF2-SHA-256 password hashing in Cloudflare Worker; plaintext passwords are never stored.
- 7-day server-side customer sessions using hashed random session tokens.
- Customer logout and session expiry.
- Customer account overview: package, monthly fee, due day, connection status, address.
- Customer-owned support ticket list.
- Ticket access is scoped to the authenticated customer account / phone.
- Admin can set or reset a customer portal password from the V2.3 customer editor.
- Setting a new password invalidates existing customer sessions.
- One deployment config file: `assets/config.js`.

## Important billing scope
V2.4 displays the monthly fee and due-day data already stored in `customers`. It does not yet implement a payment ledger, paid/unpaid invoices, payment history, or automated reconciliation. Those belong to the Billing milestone.

## Existing customers
Existing customers can remain in the database without a password. They simply cannot log in until an admin sets a portal password. No customer import is included in V2.4.

## Deployment
### Existing V2.3 D1 database
Run `worker/V2.4-MIGRATION.sql` once with the remote D1 database.

### Fresh database
Use `worker/schema.sql`, which includes the V2.4 columns and `customer_sessions` table.

### Worker
Deploy the updated `worker/src/index.js`.

### Website
Set the Worker public HTTPS URL in `assets/config.js`:

`window.RJ_API_BASE = "https://YOUR-WORKER.workers.dev";`

### Customer password
Open Admin Dashboard → Customers → Add/Edit Customer → Customer Portal Password.
Minimum 8 characters. The password is hashed in the Worker; only the customer should receive the password.

## New customer endpoints
- `POST /api/customer/login`
- `GET /api/customer/me`
- `POST /api/customer/logout`
- `GET /api/customer/tickets`
- `GET /api/customer/tickets/:id/events`
- `PATCH /api/admin/customers/:id/password`

## Security notes
- Customer authentication is not based on phone-number lookup anymore.
- Session token is stored in `sessionStorage` in the browser and only its SHA-256 hash is stored in D1.
- Keep `ADMIN_API_KEY` as a Worker secret. Never put it in `assets/config.js` or frontend code.
- Use HTTPS for the Worker and GitHub Pages site.
- Set `ALLOWED_ORIGINS` to the exact production site origins before launch.
- Consider Cloudflare Turnstile and rate limiting for `/api/customer/login` before public production use.
