# RJ NETWORK V2.2.1 — Production Deployment

This package is prepared for the next step: connecting the V2.2 customer/ticket UI to a real Cloudflare Worker + D1 database.

## 1. Create the D1 database

From `worker/`:

```bash
npx wrangler@latest d1 create rj-network
```

Copy the returned `database_id` into `worker/wrangler.toml`:

```toml
[[d1_databases]]
binding = "DB"
database_name = "rj-network"
database_id = "YOUR_REAL_D1_DATABASE_ID"
```

## 2. Initialize the database

Local test:

```bash
npx wrangler d1 execute rj-network --local --file=schema.sql
```

Production database:

```bash
npx wrangler d1 execute rj-network --remote --file=schema.sql
```

Verify:

```bash
npx wrangler d1 execute rj-network --remote --command="SELECT name FROM sqlite_master WHERE type='table' ORDER BY name"
```

## 3. Add the Admin secret

```bash
npx wrangler secret put ADMIN_API_KEY
```

Use a long random value. Do not put this key in GitHub Pages, HTML, JavaScript, localStorage, or `wrangler.toml`.

## 4. Deploy the Worker

```bash
npx wrangler deploy
```

Cloudflare will return a Worker URL similar to:

```text
https://rj-network-v2-api.<your-subdomain>.workers.dev
```

Test:

```text
GET https://YOUR-WORKER-URL/api/health
```

Expected response contains:

```json
{"ok":true}
```

## 5. Connect GitHub Pages to the Worker

Edit `assets/api.js` and set:

```js
const DEFAULT = "https://YOUR-WORKER-URL";
```

Then redeploy/push the GitHub Pages site.

Do NOT put `ADMIN_API_KEY` in `assets/api.js`.

## 6. Configure production CORS

In `worker/wrangler.toml`, keep only the real website origins in `ALLOWED_ORIGINS`.

Example:

```toml
[vars]
ALLOWED_ORIGINS = "https://rjnetworkjhaudia.github.io"
```

Remove localhost from the production deployment after testing.

## 7. Turnstile before public launch

Create a Cloudflare Turnstile widget for the support form and add its secret to the Worker:

```bash
npx wrangler secret put TURNSTILE_SECRET_KEY
```

The Worker already contains server-side Turnstile verification support.

The support page still needs the public Turnstile site-key widget added before making the form fully protected.

## 8. Admin panel

Open `admin.html` from the deployed website.

Enter:
- Worker API URL
- Admin API key

The key is kept only in the current page tab by the current implementation; it is not saved to localStorage.

## Current V2.2.1 fixes before deployment

- Removed the duplicate `customerId` HTML ID in the support form.
- Added HTML escaping to Admin customer/ticket rendering to reduce stored-XSS risk.
- Added API security response headers (`nosniff`, `no-referrer`, `no-store`).
- Declared `ADMIN_API_KEY` as a required Worker secret.

## Important

The deployment cannot be completed from this package alone because the real Cloudflare account/database ID and Worker deployment credentials belong to the site owner. Do not send Cloudflare API tokens or the Admin API key in chat.
