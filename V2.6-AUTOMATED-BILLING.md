# RJ NETWORK V2.6 — Automated Monthly Billing + Payment Reconciliation

## What changed

V2.6 builds on V2.5 Billing & Payment and adds an automated billing cycle.

### Automated monthly billing
- A Cloudflare Worker Cron runs daily at 02:15 UTC.
- The current billing month is checked every day.
- Missing invoices are generated for `active` customers with a positive `monthly_fee`.
- Invoice amount comes from the customer's current `monthly_fee`.
- Due date is calculated from `due_day`, clamped to the last day of the billing month.
- Existing customer/month invoices are skipped because the database has a unique `(customer_id, billing_year, billing_month)` constraint.

### Automatic overdue handling
Every scheduled run reconciles invoice state:
- approved payments >= invoice amount → `paid`
- pending payment exists → `pending`
- no pending payment and due date passed → `overdue`
- otherwise → `unpaid`

### Payment reconciliation
V2.6 reconciles the internal payment ledger against each invoice. It does **not** connect directly to bKash/bank APIs or automatically verify external transaction IDs.

### Audit
`billing_runs` records scheduled/manual runs, counts, status, timestamps and errors. `billing_events` records automatic invoice creation and reconciliation changes.

## New API

- `POST /api/admin/billing/run` — manually run the current billing cycle (admin only)
- `GET /api/admin/billing/automation` — recent automation run history (admin only)

## Scheduled job

`wrangler.toml` contains:

```toml
[triggers]
crons = ["15 2 * * *"]
```

Cloudflare Cron uses UTC. 02:15 UTC is 08:15 Bangladesh Standard Time (UTC+6).

## Database migration

For an existing V2.5 D1 database, run once:

```bash
npx wrangler d1 execute rj-network --remote --file=worker/V2.6-MIGRATION.sql
```

For a fresh database, use the updated `worker/schema.sql`.

## Deployment

1. Put the correct D1 `database_id` in `worker/wrangler.toml`.
2. Ensure `ADMIN_API_KEY` is configured as a Worker secret.
3. Apply `V2.6-MIGRATION.sql` to the existing V2.5 database.
4. Deploy the Worker:

```bash
cd worker
npx wrangler deploy
```

5. Confirm `/api/health`.
6. Open `billing.html` and use **Run Billing Now** once after deployment to verify the cycle.
7. Check the Automation Run History.

## Important limitation

No automatic external payment verification is implemented in V2.6. Customer-submitted payments remain `pending` until an authorized admin approves them. Direct bKash/payment-provider API reconciliation requires a separate integration and provider credentials.
